TensorRT核心概念详解

《PyTorch模型部署实战：ONNX与TensorRT全流程》· 第9章

TensorRT 概述

NVIDIA TensorRT 是一个高性能的深度学习推理（Inference）优化器和运行时库。它旨在将训练好的模型以极低的延迟和高吞吐量部署到NVIDIA GPU上。理解其核心概念是掌握模型部署的关键。

核心目标： 将训练框架（如PyTorch, TensorFlow）导出的模型，通过层融合、精度校准、内核自动调优等技术，生成高度优化的推理引擎，实现极致的推理性能。

核心工作流

典型的TensorRT部署流程包含几个关键步骤，从模型导入到最终推理执行。

  1. 模型导出： 从训练框架（如PyTorch）将模型导出为ONNX等中间格式。
  2. 模型解析： TensorRT解析器（ONNX Parser）读取中间格式文件。
  3. 网络构建与优化： Builder 根据模型定义和配置，进行图优化、层融合、选择最优内核。
  4. 引擎生成： Builder 生成可序列化的优化推理 Engine。
  5. 序列化与反序列化： 将 Engine 保存为文件（plan文件），供后续快速加载。
  6. 推理执行： 加载 Engine，创建 ExecutionContext，执行输入数据并获取输出。

五大核心组件

理解以下五个核心对象是掌握TensorRT编程接口的基础。

1. Builder (构建器)

负责从网络定义创建优化后的推理引擎。它是整个优化过程的核心控制器。

  • 配置优化参数（如精度、工作空间大小）
  • 执行层融合、内核自动调优
  • 生成序列化的引擎

2. Engine (引擎)

优化后模型的不可变表示，是Builder的输出。它包含了优化的网络和内核选择。

  • 可序列化到文件（.plan）
  • 保存了所有层的参数和最优内核
  • 反序列化后可直接用于推理

3. Context (执行上下文)

Engine的执行实例。负责管理推理时的状态，如输入/输出张量绑定、中间激活值等。

  • 一个Engine可创建多个Context
  • 持有推理执行时的中间状态
  • 执行实际的 enqueue 或 execute 方法

4. Network Definition (网络定义)

TensorRT内部对深度学习计算图的表示。可以通过解析器从文件导入，或通过API逐层手动构建。

  • 描述网络的计算图结构
  • 包含层定义、张量维度
  • Builder的输入

5. Parser (解析器)

将外部模型格式（如ONNX, Caffe, UFF）转换为TensorRT内部的Network Definition。

  • ONNX Parser最常用
  • 简化模型导入流程
  • 支持自定义层插件

精度模式

TensorRT支持多种计算精度，以在精度、速度和模型大小之间取得平衡。

精度模式 位宽 优点 缺点 适用场景
FP32 单精度浮点 32-bit 精度最高，与训练精度一致 速度最慢，内存占用最大 对精度要求极高的任务（如科研）
FP16 半精度浮点 16-bit 速度显著提升，内存减半，大多数GPU支持 可能存在精度损失（需范围调整） 绝大多数推理场景的默认选择
INT8 8位整型 8-bit 速度最快，内存仅为FP32的1/4 需要校准数据集进行量化，精度损失风险最大 边缘设备、高吞吐量服务、对延迟敏感的应用

精度选择建议： 优先尝试FP16，它在大多数现代GPU（Volta架构及以后）上能提供显著的性能提升且精度损失可控。若对延迟和吞吐有极致要求，且模型支持良好，再考虑使用INT8量化。

代码示例：核心API流程

以下伪代码展示了使用TensorRT C++ API的核心流程。

#include <NvInfer.h>
#include <NvOnnxParser.h>

// 1. 创建日志记录器、构建器和网络定义
auto logger = SampleUniquePtr<nvinfer1::ILogger>();
nvinfer1::IBuilder* builder = nvinfer1::createInferBuilder(*logger);
nvinfer1::INetworkDefinition* network = builder->createNetworkV2(...);

// 2. 使用ONNX解析器填充网络定义
auto parser = nvonnxparser::createParser(*network, *logger);
parser->parseFromFile("model.onnx", ...);

// 3. 配置构建器（设置精度、工作空间等）
builder->setMaxBatchSize(32);
builder->setFp16Mode(builder->platformHasFastFp16()); // 启用FP16
builder->setMaxWorkspaceSize(1 << 30); // 1GB

// 4. 构建优化引擎
nvinfer1::ICudaEngine* engine = builder->buildCudaEngine(*network);

// 5. 序列化引擎并保存到文件
nvinfer1::IHostMemory* serializedModel = engine->serialize();
std::ofstream planFile("model.plan", std::ios::binary);
planFile.write((const char*)serializedModel->data(), serializedModel->size());

// 6. 清理资源
serializedModel->destroy();
engine->destroy();
parser->destroy();
network->destroy();
builder->destroy();

// --- 推理阶段 ---
// 7. 从文件反序列化引擎
nvinfer1::IRuntime* runtime = nvinfer1::createInferRuntime(*logger);
std::ifstream planFile("model.plan", std::ios::binary);
std::vector<char> planData(...);
nvinfer1::ICudaEngine* loadedEngine = runtime->deserializeCudaEngine(...);

// 8. 创建执行上下文
nvinfer1::IExecutionContext* context = loadedEngine->createExecutionContext();

// 9. 准备输入/输出缓冲区（GPU内存）
void* buffers[2]; // 输入和输出
cudaMalloc(&buffers[0], inputSize);
cudaMalloc(&buffers[1], outputSize);

// 10. 执行推理
context->executeV2(buffers);

// 11. 将结果拷贝回主机并处理
cudaMemcpy(hostOutput, buffers[1], outputSize, cudaMemcpyDeviceToHost);

总结与要点

  • 工作流是基础： 理解“模型导出 -> 解析 -> 构建优化 -> 序列化 -> 加载推理”的完整链条。
  • Builder是导演： 它控制着优化过程的所有配置，并生成最终的Engine。
  • Engine是产品： 优化后的、可部署的“成品”，独立于构建过程。
  • Context是执行者： 负责管理单次或多次推理执行的具体状态。
  • 精度是权衡： FP32/FP16/INT8代表了速度、精度和内存的经典权衡，根据硬件和目标选择。
  • 序列化是关键： 将耗时的优化过程与快速的推理部署分离，提升部署效率。
