目标检测模型部署实战：YOLO系列模型转换与优化

以YOLOv5为例，详解从PyTorch到ONNX再到TensorRT的全流程部署与性能优化策略

课程概述

本课程将带领大家完成一个完整的工业级目标检测模型部署流程。我们将以当前流行的 YOLOv5 模型为例，从PyTorch训练好的模型出发，经过 ONNX 中间表示转换，最终部署到 NVIDIA TensorRT 推理引擎上，实现高性能的实时推理。

学习目标：掌握YOLO系列模型部署的核心技术栈，能够独立完成从训练模型到生产环境部署的全流程。

目标检测 模型部署 性能优化 工业实践

关键技术挑战

  • 模型兼容性：PyTorch模型到ONNX的算子支持与转换正确性
  • 后处理集成：YOLO的NMS（非极大值抑制）在部署中的实现方式
  • 精度与速度平衡：FP16/INT8量化带来的精度损失与加速收益
  • 动态尺寸支持：处理不同分辨率输入图像的动态Shape支持
  • 多平台适配：同一模型在Jetson、X86等不同硬件上的适配

部署流程总览

  1. 1 PyTorch模型导出与验证
  2. 2 ONNX格式转换与简化
  3. 3 TensorRT引擎构建与优化
  4. 4 推理代码编写与性能测试

步骤一：PyTorch模型导出

首先确保你有一个训练好的YOLOv5模型（.pt文件）。YOLOv5官方仓库提供了完善的导出脚本。

核心代码示例：

import torch

# 加载训练好的模型
model = torch.hub.load('ultralytics/yolov5', 
                       'custom', 
                       path='yolov5s.pt',
                       force_reload=True)

# 设置为评估模式
model.eval()

# 示例输入张量 (batch, channel, height, width)
dummy_input = torch.randn(1, 3, 640, 640)

# 模型前向测试
with torch.no_grad():
    output = model(dummy_input)
    print(f"输出形状: {output.shape}")
    print(f"输出类型: {type(output)}")

# 注意：YOLOv5的输出可能需要后处理
# 原始输出包含 [batch, num_anchors, 85] 格式的预测
重要提示：在导出前，务必理解YOLOv5的输出格式。原始输出包含边界框坐标、置信度和类别概率，通常需要后处理（NMS）才能得到最终检测结果。

步骤二：ONNX转换与优化

ONNX（Open Neural Network Exchange）作为中间表示，是连接训练框架与推理引擎的桥梁。

转换命令与参数解析：

# 使用YOLOv5自带的export.py脚本进行转换
python export.py --weights yolov5s.pt \
                 --include onnx \
                 --img-size 640 640 \
                 --batch-size 1 \
                 --dynamic \
                 --simplify \
                 --opset 12

# 参数说明：
# --weights: 训练好的模型权重
# --include: 导出格式，支持torchscript, onnx, engine等
# --img-size: 输入图像尺寸
# --batch-size: 批处理大小
# --dynamic: 支持动态batch和尺寸
# --simplify: 使用onnx-simplifier简化模型
# --opset: ONNX算子集版本，推荐12或以上

ONNX模型检查与可视化：

import onnx
import onnxruntime as ort
import numpy as np

# 加载并检查ONNX模型
onnx_model = onnx.load("yolov5s.onnx")
onnx.checker.check_model(onnx_model)
print(f"ONNX模型输入: {[input.name for input in onnx_model.graph.input]}")
print(f"ONNX模型输出: {[output.name for output in onnx_model.graph.output]}")

# 使用ONNX Runtime进行推理测试
ort_session = ort.InferenceSession("yolov5s.onnx")
input_name = ort_session.get_inputs()[0].name

# 准备输入数据
test_input = np.random.randn(1, 3, 640, 640).astype(np.float32)

# 运行推理
outputs = ort_session.run(None, {input_name: test_input})
print(f"ONNX推理输出形状: {outputs[0].shape}")
优化技巧：使用 onnx-simplifier 可以大幅简化模型结构，移除冗余算子，提高后续TensorRT转换的成功率。

步骤三：TensorRT引擎构建

TensorRT是NVIDIA推出的高性能深度学习推理优化器和运行时引擎。

TensorRT转换方法对比：

方法 优点 缺点 适用场景
trtexec命令行工具 简单快捷，无需编码 灵活性差，定制化困难 快速原型验证
Python API 灵活性强，可精细控制 代码复杂度高 生产环境部署
ONNX-TensorRT解析器 兼容性好，支持动态Shape 某些自定义算子支持有限 标准模型部署

使用Python API构建引擎：

import tensorrt as trt
import pycuda.driver as cuda
import pycuda.autoinit
import numpy as np

# 创建TensorRT记录器
TRT_LOGGER = trt.Logger(trt.Logger.WARNING)

def build_engine(onnx_file_path, engine_file_path, fp16_mode=True):
    builder = trt.Builder(TRT_LOGGER)
    network = builder.create_network(1 << int(trt.NetworkDefinitionCreationFlag.EXPLICIT_BATCH))
    parser = trt.OnnxParser(network, TRT_LOGGER)
    
    # 解析ONNX模型
    with open(onnx_file_path, 'rb') as model:
        if not parser.parse(model.read()):
            for error in range(parser.num_errors):
                print(parser.get_error(error))
            return None
    
    # 构建配置
    config = builder.create_builder_config()
    config.max_workspace_size = 1 << 30  # 1GB
    
    if fp16_mode and builder.platform_has_fast_fp16:
        config.set_flag(trt.BuilderFlag.FP16)
    
    # 构建引擎
    engine = builder.build_engine(network, config)
    
    # 保存引擎文件
    with open(engine_file_path, "wb") as f:
        f.write(engine.serialize())
    
    return engine

# 构建FP16精度的TensorRT引擎
engine = build_engine("yolov5s.onnx", "yolov5s_fp16.engine", fp16_mode=True)
print("TensorRT引擎构建完成！")

性能优化策略：

  • 精度选择：FP32 → FP16 → INT8，精度降低但速度提升
  • 层融合：Conv+BN+ReLU等连续层融合为单一算子
  • 内核自动调优：TensorRT自动选择最优内核实现
  • 动态Tensor内存：复用中间张量内存，减少分配开销

    def __init__(self, engine_path):
        # 加载TensorRT引擎
        self.runtime = trt.Runtime(TRT_LOGGER)
        with open(engine_path, "rb") as f:
            self.engine = self.runtime.deserialize_cuda_engine(f.read())
        
        self.context = self.engine.create_execution_context()
        self.inputs, self.outputs, self.bindings = [], [], []
        self.stream = cuda.Stream()
        
        # 分配输入输出内存
        for binding in self.engine:
            size = trt.volume(self.engine.get_binding_shape(binding))
            dtype = trt.nptype(self.engine.get_binding_dtype(binding))
            host_mem = cuda.pagelocked_empty(size, dtype)
            device_mem = cuda.mem_alloc(host_mem.nbytes)
            self.bindings.append(int(device_mem))
            
            if self.engine.binding_is_input(binding):
                self.inputs.append({'host': host_mem, 'device': device_mem})
            else:
                self.outputs.append({'host': host_mem, 'device': device_mem})
    
    def infer(self, input_image):
        # 预处理图像
        input_data = self.preprocess(input_image)
        np.copyto(self.inputs[0]['host'], input_data.ravel())

常见问题与解决方案

问题 可能原因 解决方案
ONNX转换失败 不支持的PyTorch算子 使用自定义算子实现或修改模型结构，确保使用ONNX支持的算子
TensorRT构建失败 动态Shape配置错误 明确设置最小/最优/最大尺寸，确保覆盖实际推理场景
推理精度下降明显 FP16/INT8量化误差 使用校准集进行精细量化，或混合精度策略
推理速度不达预期 内存拷贝开销大 使用异步推理、流水线处理，减少主机-设备数据传输
多batch推理效率低 引擎未优化多batch 构建时指定多batch配置，使用动态batch优化

最佳实践总结：

  1. 模型简化先行：在转换前尽量简化模型结构，移除不必要的操作
  2. 渐进式优化：先确保FP32正确性，再尝试FP16，最后考虑INT8量化
  3. 全面验证：不仅验证精度，还要验证边界情况和异常输入
  4. 文档记录：详细记录每个步骤的参数和结果，便于问题排查
  5. 版本管理：固定PyTorch、ONNX、TensorRT的版本组合，避免兼容性问题
