🔧 第一部分：ONNX中的自定义算子

ONNX（Open Neural Network Exchange）作为模型交换格式，提供了扩展机制以支持非标准算子。

1.1 注册自定义算子

在ONNX中注册自定义算子需要定义算子的输入/输出、数据类型和形状推断函数。

步骤一：定义算子原型

使用onnx.helper.make_node创建节点，并指定op_type为自定义名称。

步骤二：实现形状推断

继承onnx.shape_inference并实现infer_shapes函数。

步骤三：注册到ONNX运行时

使用onnxruntime.capi.onnxruntime_pybind11_state.register_custom_ops_library加载。

1.2 Python示例代码

import onnx
from onnx import helper, shape_inference

# 1. 创建自定义算子节点
custom_node = helper.make_node(
    'MyCustomOp',  # 算子类型名
    inputs=['input1', 'input2'],
    outputs=['output'],
    domain='com.mycompany',  # 自定义域名
    alpha=0.5  # 自定义属性
)

# 2. 创建图并添加节点
graph = helper.make_graph(
    [custom_node],
    "custom_graph",
    [helper.make_tensor_value_info('input1', onnx.TensorProto.FLOAT, [1,3,224,224]),
     helper.make_tensor_value_info('input2', onnx.TensorProto.FLOAT, [1,3,224,224])],
    [helper.make_tensor_value_info('output', onnx.TensorProto.FLOAT, [1,3,224,224])]
)

# 3. 创建模型
model = helper.make_model(graph, producer_name='my-model')
model.opset_import.extend([helper.make_opsetid('com.mycompany', 1)])

# 4. 保存模型
onnx.save(model, 'custom_model.onnx')
print("自定义算子ONNX模型已保存！")

⚙️ 第二部分：TensorRT插件开发

TensorRT插件（Plugin）是扩展TensorRT功能的核心机制，允许实现不支持的层或自定义优化。

2.1 插件开发关键组件

组件 作用 必须实现的方法
IPluginV2DynamicExt 插件基类（动态形状支持） configurePlugin, enqueue, getOutputDimensions
IPluginCreator 插件创建器工厂 createPlugin, deserializePlugin
PluginFieldCollection 插件参数传递 通过PluginField定义参数

2.2 开发流程

  1. 继承IPluginV2DynamicExt：实现核心计算逻辑和序列化。
  2. 实现IPluginCreator：提供插件的创建和反序列化。
  3. 注册插件：使用REGISTER_TENSORRT_PLUGIN宏注册到TensorRT。
  4. 编译为共享库：生成.so（Linux）或.dll（Windows）文件。
  5. 在推理中加载：使用initLibNvInferPlugins或显式加载。

注意：TensorRT插件需要严格处理内存管理和线程安全，建议使用CUDA流进行异步计算。

💻 第三部分：C++与Python插件实现

提供跨语言支持，使自定义算子既能用于高性能C++推理，也能在Python中灵活调用。

3.1 C++ TensorRT插件核心代码片段

#include "NvInferPlugin.h"
#include <cuda_runtime.h>

class MyCustomPlugin : public nvinfer1::IPluginV2DynamicExt {
public:
    MyCustomPlugin(float alpha) : mAlpha(alpha) {}

    // 核心计算函数
    int enqueue(const nvinfer1::PluginTensorDesc* inputDesc,
                const nvinfer1::PluginTensorDesc* outputDesc,
                const void* const* inputs, void* const* outputs,
                void* workspace, cudaStream_t stream) override {
        int count = 1;
        for (int i = 0; i < inputDesc[0].dims.nbDims; ++i) {
            count *= inputDesc[0].dims.d[i];
        }
        // 调用CUDA核函数（假设已实现）
        my_custom_kernel<<<(count+255)/256, 256, 0, stream>>>(
            (const float*)inputs[0], (float*)outputs[0], mAlpha, count);
        return 0;
    }

    // 序列化/反序列化
    size_t getSerializationSize() const override { return sizeof(float); }
    void serialize(void* buffer) const override { *(float*)buffer = mAlpha; }

    // 动态形状支持
    nvinfer1::DimsExprs getOutputDimensions(int outputIndex,
        const nvinfer1::DimsExprs* inputs, int nbInputs,
        nvinfer1::IExprBuilder& exprBuilder) override {
        return inputs[0]; // 输出形状与输入0相同
    }

private:
    float mAlpha;
};

// 插件创建器
class MyCustomPluginCreator : public nvinfer1::IPluginCreator {
    // 实现createPlugin, deserializePlugin等方法
};

REGISTER_TENSORRT_PLUGIN(MyCustomPluginCreator);

3.2 Python绑定与调用

使用PyBind11将C++插件暴露给Python，实现无缝集成。

// PyBind11绑定示例（简化）
#include <pybind11/pybind11.h>
#include "MyCustomPlugin.h"

PYBIND11_MODULE(my_plugin, m) {
    m.doc() = "TensorRT自定义插件Python绑定";
    
    pybind11::class_<MyCustomPlugin>(m, "MyCustomPlugin")
        .def(pybind11::init<float>())
        .def("enqueue", &MyCustomPlugin::enqueue);
        
    pybind11::class_<MyCustomPluginCreator>(m, "MyCustomPluginCreator")
        .def(pybind11::init<>())
        .def("create_plugin", &MyCustomPluginCreator::createPlugin);
}

# Python调用示例
import tensorrt as trt
import my_plugin  # 自定义插件模块

# 加载插件库
trt.init_libnvinfer_plugins(None, "")

# 构建引擎时使用自定义插件
builder = trt.Builder(logger)
network = builder.create_network(1 << int(trt.NetworkDefinitionCreationFlag.EXPLICIT_BATCH))
plugin_creator = my_plugin.MyCustomPluginCreator()
custom_layer = network.add_plugin_v2([input_tensor], plugin_creator.create_plugin("my_custom", {"alpha": 0.5}))

📊 技术对比与选择指南

方案 优点 缺点 适用场景
ONNX自定义算子 框架无关、易于移植、支持多后端 需要各推理引擎单独实现、性能可能非最优 多平台部署、研究原型、算子标准化过程
TensorRT C++插件 极致性能、完全控制内存与计算、支持动态形状 开发复杂、需CUDA知识、调试困难 生产环境、高性能要求、复杂自定义操作
Python插件绑定 开发快速、易于调试、Python生态集成 性能开销、GIL限制、部署依赖多 算法验证、快速原型、研究实验

建议：对于生产部署，优先考虑TensorRT C++插件；对于快速验证和跨平台需求，可使用ONNX自定义算子；Python绑定适合算法开发阶段。

🎯 实战总结与最佳实践

  • 提前规划：在模型设计阶段就考虑部署需求，尽量避免冷门算子。
  • 测试驱动：为自定义算子编写单元测试，覆盖数值正确性、边界条件和性能。
  • 版本管理：为插件和自定义算子维护版本号，确保与模型版本兼容。
  • 性能剖析：使用Nsight Systems/Compute分析插件性能，优化内存访问和核函数。
  • 文档齐全：记录算子的数学定义、参数含义和使用示例。
  • 回退方案：为自定义算子准备纯Python或参考实现，用于调试和验证。

掌握自定义算子支持技术，你将能够突破框架限制，部署任意复杂的模型，真正实现"模型即代码"的灵活部署。
