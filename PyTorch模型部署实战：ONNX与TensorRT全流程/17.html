第17讲：多模型流水线部署 —— 多个Engine协同、流水线并行、数据依赖管理

📚 核心概念

在复杂的AI应用场景中，单一模型往往无法满足需求。我们需要将多个模型组合成一个推理流水线（Pipeline），让它们协同工作，实现端到端的智能处理。

  • 多个Engine协同：不同模型可能运行在不同的推理引擎（TensorRT, ONNX Runtime等）上，需要统一调度。
  • 流水线并行：将处理流程划分为多个阶段，不同阶段可以并行执行，提高吞吐量。
  • 数据依赖管理：管理模型间的输入输出依赖，确保数据正确、高效地传递。

1. 多个Engine的加载与协同

使用统一的接口管理不同后端的推理引擎。

import tensorrt as trt
import onnxruntime as ort
import torch

class MultiEnginePipeline:
    def __init__(self):
        self.engines = {}

    def load_tensorrt_engine(self, name, engine_path):
        with open(engine_path, 'rb') as f:
            runtime = trt.Runtime(trt.Logger(trt.Logger.WARNING))
            engine = runtime.deserialize_cuda_engine(f.read())
        self.engines[name] = {'type': 'tensorrt', 'engine': engine}

    def load_onnx_engine(self, name, onnx_path):
        sess = ort.InferenceSession(onnx_path)
        self.engines[name] = {'type': 'onnx', 'session': sess}

    def run(self, engine_name, input_data):
        engine_info = self.engines[engine_name]
        if engine_info['type'] == 'tensorrt':
            return self._run_tensorrt(engine_info['engine'], input_data)
        elif engine_info['type'] == 'onnx':
            return self._run_onnx(engine_info['session'], input_data)

2. 流水线并行与数据依赖

使用有向无环图（DAG）描述模型间的依赖关系，并利用线程池实现并行。

from concurrent.futures import ThreadPoolExecutor
import networkx as nx

class InferencePipeline:
    def __init__(self, max_workers=4):
        self.graph = nx.DiGraph()
        self.executor = ThreadPoolExecutor(max_workers=max_workers)

    def add_node(self, name, engine, inputs, outputs):
        self.graph.add_node(name, engine=engine,
                            inputs=inputs, outputs=outputs)

    def add_dependency(self, src, dst, data_key):
        self.graph.add_edge(src, dst, data_key=data_key)

    async def run_async(self, initial_data):
        results = {**initial_data}
        # 拓扑排序确定执行顺序
        order = list(nx.topological_sort(self.graph))
        for node_name in order:
            node = self.graph.nodes[node_name]
            # 收集所需输入
            input_data = {key: results[key] for key in node['inputs']}
            # 提交异步任务
            future = self.executor.submit(node['engine'].run, input_data)
            node_output = await future
            results.update(node_output)
        return results

📊 部署策略对比

策略 优点 缺点 适用场景
同步串行 实现简单，数据流清晰 延迟高，资源利用率低 模型间强依赖，数据量小
流水线并行 高吞吐，资源利用率高 实现复杂，需要缓冲管理 处理流式数据，多批次输入
数据并行 加速单模型处理 内存消耗大，同步开销 单模型计算密集，输入可分割
混合并行 灵活，性能潜力大 调试困难，负载均衡难 复杂异构系统，生产环境

✅ 最佳实践清单

  1. profiling 先行：使用Nsight Systems/Tools分析每个模型和传输的耗时。
  2. 统一数据格式：在流水线内部使用标准张量格式（如FP16 NHWC），减少转换开销。
  3. 异步与重叠：使用CUDA Stream、异步传输和计算重叠隐藏数据搬运时间。
  4. 动态批处理：根据模型特性和输入尺寸，实现动态批处理以最大化吞吐。
  5. 优雅降级：设计备选路径，当某个引擎失败时能跳过或使用简化模型。
  6. 监控与日志：对每个阶段的耗时、内存使用进行监控，便于性能调优和问题排查。

🎯 总结

多模型流水线部署是工业级AI应用的核心技术。它要求开发者不仅理解单个模型的优化，更要掌握系统级的思维，包括任务调度、数据流设计、资源管理和性能分析。

通过结合ONNX的互操作性和TensorRT的高性能推理

关键收获：流水线的性能瓶颈往往不在计算，而在数据搬运和依赖等待。良好的设计应致力于减少数据拷贝、最大化并行度、平衡各阶段负载。
