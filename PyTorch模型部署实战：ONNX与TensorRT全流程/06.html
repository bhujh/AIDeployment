PyTorch模型部署实战

第六讲：PyTorch到ONNX转换 —— torch.onnx.export函数详解、动态轴设置、自定义算子处理

本章导览

ONNX（Open Neural Network Exchange）是模型部署中的重要中间表示。本章将深入讲解如何使用PyTorch的torch.onnx.export函数将模型转换为ONNX格式，并解决实际部署中的关键问题：动态输入尺寸设置与自定义算子的处理。

1. torch.onnx.export 核心函数详解

torch.onnx.export是PyTorch内置的模型导出函数，它将计算图转换为ONNX格式。理解其参数是成功转换的关键。

函数签名与主要参数

torch.onnx.export(
    model,                  # 要导出的PyTorch模型（必须为eval模式）
    args,                   # 模型输入，可以是张量或元组
    f,                      # 导出的ONNX文件路径或文件对象
    export_params=True,     # 是否导出模型参数
    verbose=False,          # 是否打印导出详细信息
    input_names=None,       # 输入节点名称列表
    output_names=None,      # 输出节点名称列表
    opset_version=None,     # ONNX算子集版本
    do_constant_folding=True, # 是否进行常量折叠优化
    dynamic_axes=None,      # 动态轴设置，支持可变维度
    custom_opsets=None      # 自定义算子集
)
提示： 导出前务必调用model.eval()，并确保模型在推理模式下运行，避免Dropout、BatchNorm等层的行为差异。

基础转换示例

import torch
import torchvision

# 加载预训练模型
model = torchvision.models.resnet18(pretrained=True)
model.eval()

# 创建示例输入
dummy_input = torch.randn(1, 3, 224, 224)

# 导出ONNX模型
torch.onnx.export(
    model,
    dummy_input,
    "resnet18.onnx",
    input_names=["input"],
    output_names=["output"],
    opset_version=13
)

print("导出成功！")

2. 动态轴设置（Dynamic Axes）

在实际部署中，输入尺寸（如批量大小、序列长度）可能变化。动态轴设置允许指定哪些维度可以动态变化。

动态轴参数格式

dynamic_axes = {
    'input': {0: 'batch_size', 2: 'height', 3: 'width'},  # 输入张量的动态维度
    'output': {0: 'batch_size'}  # 输出张量的动态维度
}

图像模型示例

# 支持可变批量大小和图像尺寸
dynamic_axes = {
    'input': {0: 'batch', 2: 'height', 3: 'width'},
    'output': {0: 'batch'}
}

torch.onnx.export(
    model,
    dummy_input,
    "dynamic_model.onnx",
    input_names=["input"],
    output_names=["output"],
    dynamic_axes=dynamic_axes
)

NLP模型示例

# 支持可变序列长度
dynamic_axes = {
    'input_ids': {0: 'batch', 1: 'sequence'},
    'attention_mask': {0: 'batch', 1: 'sequence'},
    'output': {0: 'batch'}
}

# 假设model是BERT类模型
torch.onnx.export(
    model,
    (input_ids, attention_mask),
    "bert_dynamic.onnx",
    input_names=["input_ids", "attention_mask"],
    output_names=["output"],
    dynamic_axes=dynamic_axes
)
注意： 并非所有推理引擎都完全支持动态维度。TensorRT对动态维度的支持有限，需根据目标部署环境进行测试。

3. 自定义算子处理

当模型包含ONNX标准算子集不支持的运算时，需要自定义算子处理。

处理方法对比

方法 适用场景 优点 缺点
算子替换 有等效标准算子组合 无需额外实现，兼容性好 可能影响性能或精度
自定义算子 复杂特殊运算 保持原逻辑，性能优化 需各后端单独实现
ATen算子 PyTorch特有运算 直接映射，简单直接 仅支持PyTorch后端

方案一：使用标准算子组合替换

# 自定义的Swish激活函数
class Swish(torch.nn.Module):
    def forward(self, x):
        return x * torch.sigmoid(x)

# 替换为等效组合
class SwishReplacement(torch.nn.Module):
    def forward(self, x):
        sigmoid = torch.sigmoid(x)
        return x * sigmoid  # ONNX已有sigmoid和mul算子

方案二：注册自定义符号函数

import torch.onnx.symbolic_registry as sym_registry

# 定义自定义算子的符号函数
def my_custom_op_symbolic(g, input, scale):
    # g: GraphContext
    # 返回ONNX算子表示
    return g.op("MyCustomOp", input, scale_f=scale)

# 注册符号函数（需指定opset版本）
sym_registry.register_op('my_custom_op', my_custom_op_symbolic, '', 13)

# 现在包含my_custom_op的模型可以正常导出
torch.onnx.export(model, dummy_input, "custom.onnx")
最佳实践： 优先尝试用现有ONNX算子组合实现自定义逻辑。如果必须使用自定义算子，需确保目标推理引擎（如TensorRT）支持该自定义算子或提供对应的插件实现。

4. 完整工作流程与验证

模型验证代码

import onnx
import onnxruntime as ort
import numpy as np

# 1. 检查模型格式是否正确
onnx_model = onnx.load("model.onnx")
onnx.checker.check_model(onnx_model)
print("ONNX模型格式验证通过！")

# 2. 使用ONNX Runtime推理验证
ort_session = ort.InferenceSession("model.onnx")

# 准备输入（与导出时类型一致）
input_data = np.random.randn(1, 3, 224, 224).astype(np.float32)

# 运行推理
ort_inputs = {ort_session.get_inputs()[0].name: input_data}
ort_outputs = ort_session.run(None, ort_inputs)

print("ONNX Runtime推理成功！输出形状:", ort_outputs[0].shape)

# 3. 与PyTorch结果对比（可选）
with torch.no_grad():
    torch_output = model(torch.from_numpy(input_data))
    diff = np.abs(torch_output.numpy() - ort_outputs[0]).max()
    print(f"PyTorch与ONNX Runtime最大差异: {diff}")

5. 常见问题与解决方案

问题1：导出失败

可能原因： 模型包含ONNX不支持的Python控制流或复杂数据结构。

解决方案：

  • 使用torch.jit.script或torch.jit.trace先处理模型
  • 将控制流改为基于张量的操作
  • 检查模型是否包含非张量输出

问题2：动态轴不生效

可能原因： 动态轴设置格式错误或推理引擎不支持。

解决方案：

  • 确认dynamic_axes字典格式正确
  • 使用ONNX Runtime验证动态轴是否生效
  • 查阅目标推理引擎的文档

问题3：精度下降

可能原因： 算子实现差异或数据类型转换问题。

解决方案：

  • 使用opset_version指定更高版本
  • 检查模型中的数据类型是否一致
  • 对比中间层输出定位问题
