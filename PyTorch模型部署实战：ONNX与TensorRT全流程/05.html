第五讲：ONNX格式详解

ONNX计算图结构、算子集、数据类型、模型元数据

一、ONNX概述

ONNX（Open Neural Network Exchange）是一个开放的格式，用于表示深度学习模型。它允许模型在不同的框架之间进行转换，从而实现跨平台部署。

🎯 核心目标：实现模型在不同框架（如PyTorch, TensorFlow, MXNet）之间的互操作性，简化部署流程。

ONNX作为桥梁连接训练框架与推理引擎

二、ONNX计算图结构

ONNX使用有向无环图（DAG）来表示模型的计算过程。图中包含节点（算子）、边（数据张量）和初始化器（常量）。

📊 计算图组成

  • 节点（Node）：代表一个算子或操作（如Conv, Relu）。
  • 边（Edge）：代表张量数据流，连接各个节点。
  • 初始化器（Initializer）：存储模型中的权重和偏置等常量。
  • 输入/输出（Input/Output）：定义图的入口和出口。

🔗 图示例（简化）

# 伪代码表示一个简单的线性层+激活函数
Input X -> MatMul (W) -> Add (B) -> Relu -> Output Y
# 对应ONNX图：
# 节点: MatMul, Add, Relu
# 边: X, W, B, 中间结果, Y

💡 注意：ONNX图是静态的，意味着图的结构在导出时就已经固定，不支持动态控制流（如循环、条件判断）。

三、ONNX算子集（Opset）

ONNX定义了一套标准的算子集合，每个算子都有其特定的版本（opset version）。随着ONNX的发展，算子集会不断更新和扩展。

算子类别 示例算子 主要功能 支持版本
张量操作 Reshape, Concat, Slice 改变张量形状、连接、切片 opset 1+
神经网络 Conv, BatchNormalization, Gemm 卷积、批归一化、全连接 opset 1+
激活函数 Relu, Sigmoid, Tanh 非线性激活 opset 1+
规约操作 ReduceMean, ReduceSum 统计计算 opset 1+
控制流（有限） Loop, If 循环与条件 opset 11+

🔧 Opset版本选择：导出ONNX模型时需要指定opset版本。较高的版本支持更多算子，但需确保推理引擎兼容该版本。

# PyTorch导出时指定opset版本
torch.onnx.export(model, dummy_input, "model.onnx",
                  opset_version=13,  # 指定版本
                  input_names=['input'],
                  output_names=['output'])

四、ONNX数据类型

ONNX定义了丰富的数据类型，以支持不同精度和类型的张量。

🧮 主要数据类型

  • FLOAT：32位浮点数（最常用）
  • FLOAT16：16位半精度浮点数
  • INT32, INT64：32/64位整数
  • UINT8：8位无符号整数（用于量化）
  • BOOL：布尔类型
  • STRING：字符串类型（较少使用）

📐 张量形状表示

ONNX使用符号维度支持动态形状，常用占位符：

  • batch_size：批处理大小
  • seq_len：序列长度
  • -1：表示该维度可变

五、模型元数据（Metadata）

ONNX模型除了计算图外，还包含重要的元数据信息，用于描述模型的背景、版本和生产者等。

字段名 说明 示例
producer_name 生成模型的框架名称 pytorch
producer_version 框架版本 1.12.0
ir_version ONNX中间表示版本 8
opset_import 引用的算子集版本 ai.onnx:13
doc_string 模型描述文档 ResNet50图像分类模型
model_version 模型版本号 1

🔍 查看元数据示例代码

import onnx

model = onnx.load("model.onnx")
# 打印模型元数据
print("生产者:", model.producer_name)
print("版本:", model.producer_version)
print("IR版本:", model.ir_version)
print("算子集:", model.opset_import)
print("文档:", model.doc_string)

七、总结与最佳实践

✅ 最佳实践

  1. 导出时指定合适的opset版本，平衡功能与兼容性。
  2. 使用动态形状提高模型灵活性，但需测试边界情况。
  3. 导出后使用onnx.checker验证模型正确性。
  4. 利用onnx.helper工具修改和优化模型。
  5. 记录完整的元数据，便于后续维护和版本管理。

⚠️ 常见陷阱

  • 动态控制流（如循环）支持有限，需谨慎使用。
  • 某些PyTorch算子可能没有对应的ONNX算子。
  • 不同推理引擎对ONNX标准的支持程度不同。
  • 数据类型转换可能导致精度损失。
