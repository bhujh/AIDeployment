课程概述

本章节将深入讲解如何将训练好的ONNX模型转换为高性能的TensorRT引擎。我们将覆盖三种核心方法：trtexec命令行工具、Python API解析器以及详细的构建配置。掌握这些技能是模型部署工程师从实验到生产的关键一步。

一、trtexec命令行工具

trtexec是TensorRT自带的一个功能强大的命令行工具，无需编写代码即可快速完成模型转换与性能测试。

1.1 基本用法

# 基础转换命令
trtexec --onnx=model.onnx --saveEngine=model.engine

# 指定精度（FP16/FP32/INT8）
trtexec --onnx=model.onnx --fp16 --saveEngine=model_fp16.engine
trtexec --onnx=model.onnx --int8 --saveEngine=model_int8.engine

# 指定工作空间大小（单位：MB）
trtexec --onnx=model.onnx --workspace=2048 --saveEngine=model.engine

1.2 性能分析模式

# 性能基准测试
trtexec --onnx=model.onnx \
        --shapes=input:1x3x224x224 \
        --iterations=100 \
        --avgRuns=10 \
        --duration=5 \
        --exportTimes=times.json
提示： trtexec非常适合快速原型验证和基准测试，但在生产环境中通常使用Python API进行更精细的控制。

二、Python API解析器

TensorRT的Python API提供了最灵活的控制方式，适合集成到自动化部署流水线中。

2.1 核心组件

组件 作用 常用类/函数
Builder 创建引擎配置和构建引擎 trt.Builder, create_builder_config
Parser 解析ONNX模型为TensorRT网络 trt.OnnxParser
Network 中间表示，可进行自定义修改 trt.INetworkDefinition
Config 构建配置，控制精度、内存等 trt.IBuilderConfig

2.2 完整转换示例

import tensorrt as trt
import os

def build_engine_from_onnx(onnx_file_path, engine_file_path, fp16_mode=True):
    """从ONNX文件构建TensorRT引擎"""
    TRT_LOGGER = trt.Logger(trt.Logger.WARNING)
    builder = trt.Builder(TRT_LOGGER)
    network = builder.create_network(1 << int(trt.NetworkDefinitionCreationFlag.EXPLICIT_BATCH))
    parser = trt.OnnxParser(network, TRT_LOGGER)
    
    # 解析ONNX模型
    with open(onnx_file_path, 'rb') as model:
        if not parser.parse(model.read()):
            print('ERROR: Failed to parse the ONNX file.')
            for error in range(parser.num_errors):
                print(parser.get_error(error))
            return None
    
    # 构建配置
    config = builder.create_builder_config()
    config.max_workspace_size = 1 << 30  # 1GB
    if fp16_mode and builder.platform_has_fast_fp16:
        config.set_flag(trt.BuilderFlag.FP16)
    
    # 构建引擎
    engine = builder.build_engine(network, config)
    if engine is None:
        print('ERROR: Failed to build engine.')
        return None
    
    # 保存引擎
    with open(engine_file_path, 'wb') as f:
        f.write(engine.serialize())
    
    print(f'Engine saved to {engine_file_path}')
    return engine

# 使用示例
if __name__ == '__main__':
    build_engine_from_onnx('resnet50.onnx', 'resnet50.engine')

三、构建配置详解

构建配置决定了引擎的最终性能、精度和兼容性，是优化部署的关键。

3.1 精度配置

  • FP32模式：默认模式，精度最高，速度最慢
  • FP16模式：半精度，速度提升明显，精度损失可接受
  • INT8模式：需要校准，速度最快，精度损失需评估

3.2 关键配置选项

配置项 说明 示例代码
工作空间大小 GPU内存分配上限 config.max_workspace_size = 1 << 30
批处理大小 动态/静态批处理设置 builder.max_batch_size = 32
层融合优化 自动融合卷积、BN、激活层 config.set_flag(trt.BuilderFlag.FP16)
动态形状 支持可变输入尺寸 profile = builder.create_optimization_profile()

3.3 INT8校准配置

class Calibrator(trt.IInt8EntropyCalibrator2):
    def __init__(self, calibration_data, cache_file='calibration.cache'):
        super().__init__()
        self.data = calibration_data
        self.cache_file = cache_file
        self.index = 0
        
    def get_batch_size(self):
        return 1
    
    def get_batch(self, names):
        if self.index < len(self.data):
            batch = self.data[self.index]
            self.index += 1
            return [batch.data_ptr()]
        return None
    
    def read_calibration_cache(self):
        if os.path.exists(self.cache_file):
            with open(self.cache_file, 'rb') as f:
                return f.read()
        return None
    
    def write_calibration_cache(self, cache):
        with open(self.cache_file, 'wb') as f:
            f.write(cache)

# 启用INT8校准
config.int8_calibrator = Calibrator(calibration_data)
config.set_flag(trt.BuilderFlag.INT8)

四、最佳实践与常见问题

4.1 转换流程检查清单

  1. ✅ 验证ONNX模型版本与TensorRT兼容性
  2. ✅ 检查模型算子是否全部支持（使用polygraphy工具）
  3. ✅ 根据部署硬件选择合适精度（FP16/INT8）
  4. ✅ 设置合理的工作空间大小（通常1-4GB）
  5. ✅ 保存构建日志以便调试
  6. ✅ 验证转换后引擎的精度损失（<1%通常可接受）

4.2 常见错误与解决方案

错误类型 可能原因 解决方案
解析失败 ONNX版本不兼容、算子不支持 使用onnx-simplifier简化模型，更新TensorRT版本
内存不足 工作空间设置过小 增加max_workspace_size，尝试FP16/INT8
精度损失大 FP16/INT8量化误差 使用混合精度，对敏感层保持FP32
推理速度慢 未启用层融合、批处理大小不合适 检查构建标志，优化批处理大小
高级技巧： 对于生产环境，建议实现自动化转换流水线，包含模型验证、自动精度选择、性能回归测试等环节。
