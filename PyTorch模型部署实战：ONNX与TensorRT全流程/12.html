TensorRT推理执行全流程

深入掌握高性能推理引擎的核心执行步骤

概述

TensorRT推理执行是将优化后的模型在GPU上实际运行的过程，涉及内存管理、数据流控制和执行调度。本讲将详细分解四个核心环节：分配设备内存、数据传输、执行上下文和异步推理。

1. 分配设备内存

在GPU上执行推理前，必须为输入和输出张量分配显存。TensorRT通过IExecutionContext获取绑定信息，然后分配对应的主机和设备内存缓冲区。

关键步骤：

  1. 获取绑定数量：通过执行上下文获取模型输入输出绑定的总数。
  2. 查询绑定信息：获取每个绑定的名称、数据类型和维度。
  3. 计算内存大小：根据数据类型和维度计算所需内存字节数。
  4. 分配主机内存：使用malloc或new在CPU上分配内存。
  5. 分配设备内存：使用cudaMalloc在GPU上分配显存。

内存分配示例代码：

#include <NvInfer.h>
#include <cuda_runtime_api.h>

// 创建执行上下文
nvinfer1::IExecutionContext* context = engine->createExecutionContext();

// 获取绑定数量
int numBindings = engine->getNbBindings();

// 准备主机和设备内存指针数组
void* hostBuffers[numBindings];
void* deviceBuffers[numBindings];

for (int i = 0; i < numBindings; ++i) {
    // 获取绑定维度
    nvinfer1::Dims dims = engine->getBindingDimensions(i);
    
    // 获取数据类型
    nvinfer1::DataType dtype = engine->getBindingDataType(i);
    
    // 计算数据大小
    size_t size = calculateSize(dims, dtype);
    
    // 分配主机内存
    hostBuffers[i] = malloc(size);
    
    // 分配设备内存
    cudaMalloc(&deviceBuffers[i], size);
    
    // 记录绑定是输入还是输出
    if (engine->bindingIsInput(i)) {
        std::cout << "绑定 " << i << " 是输入: " 
                  << engine->getBindingName(i) << std::endl;
    } else {
        std::cout << "绑定 " << i << " 是输出: " 
                  << engine->getBindingName(i) << std::endl;
    }
}
注意： 实际应用中应考虑内存对齐要求，并使用智能指针或RAII类管理内存生命周期，避免内存泄漏。

2. 数据传输

数据需要在主机(CPU)内存和设备(GPU)内存之间传输。这是推理流程中的关键性能瓶颈之一，需要优化以减少传输开销。

1

主机到设备 (H2D)

将预处理后的输入数据从主机内存拷贝到设备内存。

  • 使用cudaMemcpy同步拷贝
  • 或使用cudaMemcpyAsync异步拷贝
  • 考虑使用固定内存(pinned memory)加速传输
2

设备到主机 (D2H)

将推理结果从设备内存拷贝回主机内存。

  • 在推理完成后执行
  • 异步推理中需等待流同步
  • 注意内存对齐和格式转换

数据传输代码示例：

// 准备输入数据（示例：随机数据）
float* hostInput = (float*)hostBuffers[inputIndex];
for (int i = 0; i < inputSize; ++i) {
    hostInput[i] = static_cast<float>(rand()) / RAND_MAX;
}

// 同步拷贝：主机到设备
cudaMemcpy(deviceBuffers[inputIndex], 
           hostBuffers[inputIndex], 
           inputSize * sizeof(float), 
           cudaMemcpyHostToDevice);

// 执行推理后，从设备拷贝结果回主机
cudaMemcpy(hostBuffers[outputIndex], 
           deviceBuffers[outputIndex], 
           outputSize * sizeof(float), 
           cudaMemcpyDeviceToHost);

// 处理输出数据
float* hostOutput = (float*)hostBuffers[outputIndex];
for (int i = 0; i < 10; ++i) { // 打印前10个结果
    std::cout << "输出[" << i << "] = " << hostOutput[i] << std::endl;
}
传输类型 函数 同步/异步 使用场景
主机→设备 cudaMemcpy 同步 简单应用、调试
主机→设备 cudaMemcpyAsync 异步 流水线优化、高性能应用
设备→主机 cudaMemcpy 同步 立即需要结果
设备→设备 cudaMemcpy 同步 多GPU间数据传输

3. 执行上下文

执行上下文(IExecutionContext)是TensorRT推理的执行环境，管理推理状态、绑定信息和执行配置。

上下文的主要功能：

  • 绑定设置：将设备内存缓冲区与模型输入输出绑定
  • 执行推理：同步(execute)或异步(enqueue)执行
  • 动态形状：处理可变尺寸的输入（如果引擎支持）
  • 优化配置：设置迭代次数、工作空间大小等

执行上下文使用示例：

// 创建执行上下文
nvinfer1::IExecutionContext* context = engine->createExecutionContext();

// 设置输入维度（对于动态形状）
if (engine->hasImplicitBatchDimension()) {
    // 隐式批处理模式
    context->setBindingDimensions(inputIndex, nvinfer1::Dims4{batchSize, 3, 224, 224});
} else {
    // 显式批处理模式
    context->setInputShape(inputName, nvinfer1::Dims{4, {batchSize, 3, 224, 224}});
}

// 同步执行推理
bool success = context->execute(batchSize, deviceBuffers);

// 或者使用V2接口（推荐）
bool success = context->executeV2(deviceBuffers);

if (!success) {
    std::cerr << "推理执行失败!" << std::endl;
    return -1;
}

// 释放上下文资源（重要！）
context->destroy();
最佳实践： 对于高性能应用，建议使用executeV2或enqueueV2接口，它们支持更高效的执行路径和异步操作。

4. 异步推理

异步推理允许重叠计算和数据传输，最大化GPU利用率，是高性能部署的关键技术。

异步推理的优势：

  • 计算与传输重叠：GPU计算同时进行下一次的数据传输
  • 多流并行：使用多个CUDA流并行执行多个推理任务
  • 流水线优化：将预处理、推理、后处理组成流水线
  • 更高吞吐量：显著提高系统整体吞吐量

异步推理实现步骤：

  1. 创建CUDA流：cudaStreamCreate(&stream)
  2. 使用固定内存(pinned memory)加速主机到设备传输
  3. 异步拷贝输入数据：cudaMemcpyAsync
  4. 异步执行推理：context->enqueueV2()
  5. 异步拷贝输出数据：cudaMemcpyAsync
  6. 同步流或使用回调函数处理结果

异步推理完整示例：

#include <cuda_runtime_api.h>
#include <NvInfer.h>

// 创建CUDA流
cudaStream_t stream;
cudaStreamCreate(&stream);

// 使用固定内存分配主机内存（加速传输）
float* hostInputPinned;
float* hostOutputPinned;
cudaMallocHost(&hostInputPinned, inputSize * sizeof(float));
cudaMallocHost(&hostOutputPinned, outputSize * sizeof(float));

// 准备输入数据
prepareInputData(hostInputPinned, inputSize);

// 异步拷贝：主机到设备
cudaMemcpyAsync(deviceBuffers[inputIndex], 
                hostInputPinned, 
                inputSize * sizeof(float), 
                cudaMemcpyHostToDevice, 
                stream);

// 异步执行推理
context->enqueueV2(deviceBuffers, stream, nullptr);

// 异步拷贝：设备到主机
cudaMemcpyAsync(hostOutputPinned, 
                deviceBuffers[outputIndex], 
                outputSize * sizeof(float), 
                cudaMemcpyDeviceToHost, 
                stream);

// 等待流完成（同步点）
cudaStreamSynchronize(stream);

// 处理结果
processOutput(hostOutputPinned, outputSize);

// 清理资源
cudaStreamDestroy(stream);
cudaFreeHost(hostInputPinned);
cudaFreeHost(hostOutputPinned);
技术 同步方式 吞吐量 延迟 实现复杂度
同步推理 完全同步 低 高 简单
异步推理(单流) 流内同步 中 中 中等
异步推理(多流) 事件同步 高 低 复杂
流水线并行 生产者-消费者 最高 最低 最复杂

总结与最佳实践

内存管理

  • 使用RAII模式管理内存生命周期
  • 对于频繁传输的数据使用固定内存
  • 及时释放不再使用的内存
  • 监控GPU内存使用情况

性能优化

  • 优先使用异步推理模式
  • 合理设置批处理大小
  • 使用TensorRT的混合精度推理
  • 考虑使用TensorRT的DLA(深度学习加速器)

错误处理

  • 检查所有CUDA API返回值
  • 使用cudaGetLastError()排查错误
  • 实现完善的日志系统
  • 添加异常安全机制

完整推理流程代码框架：

// TensorRT推理执行框架
class TensorRTInferencer {
public:
    TensorRTInferencer(const std::string& enginePath) {
        // 1. 加载引擎
        loadEngine(enginePath);
        
        // 2. 创建执行上下文
        context = engine->createExecutionContext();
        
        // 3. 分配内存
        allocateMemory();
        
        // 4. 创建CUDA流
        cudaStreamCreate(&stream);
    }
    
    ~TensorRTInferencer() {
        // 释放所有资源
        freeMemory();
        cudaStreamDestroy(stream);
        context->destroy();
        // ... 其他清理
    }
    
    void infer(const std::vector<float>& input) {
        // 1. 准备输入数据
        prepareInput(input);
        
        // 2. 异步H2D传输
        cudaMemcpyAsync(deviceInput, hostInput, ...);
        
        // 3. 异步执行推理
        context->enqueueV2(deviceBuffers, stream, nullptr);
        
        // 4. 异步D2H传输
        cudaMemcpyAsync(hostOutput, deviceOutput, ...);
        
        // 5. 同步流
        cudaStreamSynchronize(stream);
        
        // 6. 处理输出
        processOutput();
    }
    
private:
    nvinfer1::ICudaEngine* engine;
    nvinfer1::IExecutionContext* context;
    cudaStream_t stream;
    // ... 其他成员变量
};
课程建议： 在实际项目中，建议封装成类来管理TensorRT推理的完整生命周期，确保资源正确释放，并提供线程安全的接口。
