模型转换流程

二、TFLite转换器（TFLite Converter）

TFLite转换器是将TensorFlow模型（SavedModel, Keras, Concrete functions）转换为TFLite格式（.tflite）的核心工具。支持多种优化选项。

2.1 转换方式

  • 命令行转换：使用tflite_convert工具
  • Python API转换：使用tf.lite.TFLiteConverter
  • TensorFlow.js转换：从TensorFlow.js模型转换

2.2 基础转换示例

import tensorflow as tf

# 加载已训练的Keras模型
model = tf.keras.models.load_model('my_model.h5')

# 创建转换器
converter = tf.lite.TFLiteConverter.from_keras_model(model)

# 设置转换选项（可选）
converter.optimizations = [tf.lite.Optimize.DEFAULT]

# 转换为TFLite格式
tflite_model = converter.convert()

# 保存模型
with open('model.tflite', 'wb') as f:
    f.write(tflite_model)

print("模型转换成功！模型大小：", len(tflite_model) / 1024, "KB")

三、训练后量化（Post-training Quantization）

在模型训练完成后应用量化，无需重新训练。平衡精度与性能的常用方法。

3.1 量化类型对比

量化类型 权重 激活值 精度损失 适用场景
动态范围量化 INT8 FP32 小 快速原型，CPU推理
全整数量化 INT8 INT8 中 CPU/Edge TPU，需要整型推理
浮点16量化 FP16 FP16 很小 GPU推理，精度要求高

3.2 全整数量化示例

import tensorflow as tf

# 加载模型
converter = tf.lite.TFLiteConverter.from_saved_model('saved_model_dir')

# 设置全整数量化
converter.optimizations = [tf.lite.Optimize.DEFAULT]
converter.representative_dataset = representative_data_gen  # 提供代表性数据集
converter.target_spec.supported_ops = [tf.lite.OpsSet.TFLITE_BUILTINS_INT8]
converter.inference_input_type = tf.uint8  # 或 tf.int8
converter.inference_output_type = tf.uint8 # 或 tf.int8

# 转换
tflite_quant_model = converter.convert()

# 保存量化模型
with open('model_quant_int8.tflite', 'wb') as f:
    f.write(tflite_quant_model)

注意：代表性数据集应包含100-500个典型输入样本，用于校准激活值的动态范围。

四、量化感知训练（Quantization-aware Training, QAT）

在训练过程中模拟量化效果，让模型提前适应低精度计算，通常获得比训练后量化更好的精度。

4.1 QAT工作流程

  1. 在预训练FP32模型中插入“伪量化”节点
  2. 微调模型（通常1-10个epoch）
  3. 使用TFLite转换器导出为真正的量化模型

4.2 QAT代码示例

import tensorflow as tf
import tensorflow_model_optimization as tfmot

# 加载预训练模型
model = tf.keras.models.load_model('pretrained.h5')

# 应用量化感知训练
quantize_model = tfmot.quantization.keras.quantize_model
qat_model = quantize_model(model)

# 编译并微调（使用较小学习率）
qat_model.compile(optimizer='adam',
                  loss='categorical_crossentropy',
                  metrics=['accuracy'])

qat_model.fit(train_images, train_labels,
              epochs=5,
              validation_data=(val_images, val_labels))

# 保存QAT模型
qat_model.save('qat_model.h5')

# 转换为TFLite量化模型
converter = tf.lite.TFLiteConverter.from_keras_model(qat_model)
converter.optimizations = [tf.lite.Optimize.DEFAULT]
tflite_qat_model = converter.convert()

五、移动端集成（Android/iOS）

将量化后的TFLite模型部署到移动设备，实现端侧AI推理。

5.1 Android集成

  • 依赖添加：在build.gradle中添加TFLite依赖
  • 模型放置：将.tflite文件放入app/src/main/assets
  • 使用Interpreter：加载并运行模型
// Kotlin示例：加载并运行TFLite模型
import org.tensorflow.lite.Interpreter
import java.nio.ByteBuffer
import java.nio.ByteOrder

class TFLiteClassifier(context: Context) {
    private lateinit var interpreter: Interpreter
    
    init {
        // 1. 加载模型
        val modelFile = loadModelFile(context, "model_quant.tflite")
        val options = Interpreter.Options()
        options.setNumThreads(4) // 设置线程数
        
        // 2. 创建解释器
        interpreter = Interpreter(modelFile, options)
    }
    
    fun infer(inputData: FloatArray): FloatArray {
        // 3. 准备输入输出
        val inputBuffer = ByteBuffer.allocateDirect(4 * inputData.size)
            .order(ByteOrder.nativeOrder())
            .asFloatBuffer()
        inputBuffer.put(inputData)
        
        val output = Array(1) { FloatArray(10) } // 假设输出10类
        
        // 4. 运行推理
        interpreter.run(inputBuffer, output)
        
        return output[0]
    }
    
    private fun loadModelFile(context: Context, filename: String): ByteBuffer {
        val assetFile = context.assets.open(filename)
        val modelBuffer = ByteBuffer.allocateDirect(assetFile.available())
            .order(ByteOrder.nativeOrder())
        val bytes = ByteArray(assetFile.available())
        assetFile.read(bytes)
        modelBuffer.put(bytes)
        return modelBuffer
    }
}

5.2 iOS集成

  • 添加依赖：通过CocoaPods添加TensorFlowLiteSwift
  • 模型添加：将.tflite文件添加到Xcode项目
  • 使用Swift API：简洁的Swift接口
// Swift示例：iOS端TFLite推理
import TensorFlowLite

class TFLiteModelHandler {
    private var interpreter: Interpreter?
    
    init() {
        // 1. 定位模型文件
        guard let modelPath = Bundle.main.path(
            forResource: "model_quant", 
            ofType: "tflite"
        ) else { return }
        
        // 2. 创建解释器
        do {
            interpreter = try Interpreter(modelPath: modelPath)
            try interpreter?.allocateTensors()
        } catch {
            print("Failed to create interpreter: \(error)")
        }
    }
    
    func runInference(inputData: Data) -> [Float]? {
        guard let interpreter = interpreter else { return nil }
        
        do {
            // 3. 复制输入数据
            try interpreter.copy(inputData, toInputAt: 0)
            
            // 4. 运行推理
            try interpreter.invoke()
            
            // 5. 获取输出
            let outputTensor = try interpreter.output(at: 0)
            let outputSize = outputTensor.shape.dimensions.reduce(1, *)
            let outputData = outputTensor.data
            
            // 转换为Float数组
            return outputData.withUnsafeBytes {
                Array(UnsafeBufferPointer(
                    start: $0.baseAddress!.assumingMemoryBound(to: Float.self),
                    count: outputSize
                ))
            }
        } catch {
            print("Inference failed: \(error)")
            return nil
        }
    }
}

六、最佳实践与性能对比

6.1 量化策略选择指南

场景 推荐方法 预期收益 注意事项
快速原型部署 动态范围量化 体积减少75%，速度提升2-3倍 精度损失较小，部署最简单
移动端CPU推理 全整数量化（PTQ） 最大性能，体积最小 需要代表性数据集校准
高精度要求场景 量化感知训练（QAT） 精度接近FP32，体积减少75% 需要额外训练时间
GPU加速推理 FP16量化 速度提升，精度几乎无损 需要硬件支持FP16

6.2 性能对比数据（示例）

关键建议：

  • 始终从动态范围量化开始，评估精度损失
  • 对于新模型，考虑直接使用量化感知训练
  • 使用TFLite基准测试工具量化性能：benchmark_model
  • 在真实设备上测试，模拟器性能可能与实际不同
