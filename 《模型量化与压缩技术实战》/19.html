一、ONNX格式详解

ONNX（Open Neural Network Exchange）是一个开放的格式，用于表示深度学习模型。它使得模型可以在不同框架之间进行转移，提高了模型的互操作性。

核心价值： ONNX 解决了AI生态系统中框架碎片化的问题，允许开发者在最适合的框架中训练模型，然后转移到最适合的生产环境中进行部署。

1.1 ONNX 核心组件

  • 计算图（Graph）：由节点（Nodes）和边（Tensors）组成的有向无环图（DAG）。
  • 操作符集（Operator Set）：定义了图中节点可执行的操作（如Conv、Relu、MatMul）。
  • 张量（Tensor）：带有类型和形状的多维数组，是图中流动的数据。
  • 模型元数据（Metadata）：包含模型版本、作者等描述信息。

# ONNX 模型 protobuf 结构概要
ModelProto
├── ir_version          # ONNX版本号
├── producer_name       # 生成工具（如PyTorch）
├── producer_version    # 工具版本

│   ├── output         # 模型输出
│   └── initializer    # 权重常量
├── opset_import       # 引用的操作符集
└── metadata_props     # 额外元数据

二、PyTorch/TensorFlow 到 ONNX 转换

2.1 PyTorch 转换

使用 torch.onnx.export() 函数将 PyTorch 模型转换为 ONNX 格式。

import torch
import torchvision

# 加载预训练模型
model = torchvision.models.resnet18(pretrained=True)
model.eval()

# 创建示例输入
dummy_input = torch.randn(1, 3, 224, 224)

# 导出为ONNX
torch.onnx.export(
    model,                  # 模型
    dummy_input,           # 模型输入（元组也可）
    "resnet18.onnx",       # 保存路径
    export_params=True,    # 是否保存训练参数
    opset_version=13,      # ONNX算子集版本
    do_constant_folding=True,  # 是否执行常量折叠优化
    input_names=['input'], # 输入名
    output_names=['output'], # 输出名
    dynamic_axes={         # 动态轴配置（支持可变batch）
        'input': {0: 'batch_size'},
        'output': {0: 'batch_size'}
    }
)
print("导出成功！")

2.2 TensorFlow 转换

使用 tf2onnx 工具转换 TensorFlow/Keras 模型。

# 方法1：使用 tf2onnx 命令行工具
# pip install tf2onnx
# python -m tf2onnx.convert \
#   --saved-model tensorflow-model-path \
#   --output model.onnx \
#   --opset 13

# 方法2：Python API
import tf2onnx
import tensorflow as tf

# 加载SavedModel
model = tf.keras.models.load_model('my_model.h5')

# 转换
spec = (tf.TensorSpec((None, 224, 224, 3), tf.float32, name="input"),)
output_path = "model.onnx"

model_proto, _ = tf2onnx.convert.from_keras(
    model, 
    input_signature=spec,
    opset=13,
    output_path=output_path
)
print(f"模型已保存至 {output_path}")
转换注意事项：
  • 确保模型处于推理模式（如PyTorch的model.eval()）
  • 提供正确的输入形状，尤其是动态维度
  • 检查ONNX算子集版本是否支持模型中的所有操作
  • 转换后务必使用ONNX Runtime验证模型正确性

三、ONNX 模型优化

ONNX 模型可以通过多种工具进行优化，以提升推理速度、减少内存占用。

3.1 使用 ONNX Runtime 优化

import onnx
from onnxruntime.transformers import optimizer

# 加载原始模型
model_path = "model.onnx"
onnx_model = onnx.load(model_path)

# 基础优化（常量折叠、冗余节点消除等）
optimized_model = optimizer.optimize_model(
    model_path,
    model_type='bert',  # 可选 'bert', 'gpt2', 'vit' 等
    num_heads=12,       # 注意力头数（针对Transformer）
    hidden_size=768
)

# 保存优化后模型
optimized_model.save_model_to_file("model_optimized.onnx")

# 使用图优化API
from onnxruntime.transformers import onnx_model
onnx_model = onnx_model.OnnxModel(onnx.load(model_path))
onnx_model.remove_unused_constant()
onnx_model.use_dynamic_axes()
onnx.save(onnx_model.model, "model_dynamic.onnx")

3.2 优化技术对比

优化技术 描述 效果 适用场景
常量折叠 将计算图中的常量表达式预先计算 减少计算节点，简化图结构 所有模型
算子融合 将多个小算子合并为一个大算子 减少内核启动开销，提升速度 Conv+BN+ReLU等连续操作
冗余消除 删除无用的节点和边 减小模型大小，提升加载速度 所有模型
精度转换 FP32 → FP16/INT8 量化 大幅减少内存，提升推理速度 部署到边缘设备
内存优化 重用内存缓冲区 减少内存占用峰值 大模型或内存受限环境

四、跨框架部署实战

ONNX 跨框架部署架构

4.1 使用 ONNX Runtime 推理

import onnxruntime as ort
import numpy as np

# 创建推理会话
providers = ['CUDAExecutionProvider', 'CPUExecutionProvider']
session = ort.InferenceSession("model_optimized.onnx", providers=providers)

# 获取输入输出信息
input_name = session.get_inputs()[0].name
output_name = session.get_outputs()[0].name

# 准备输入数据
input_data = np.random.randn(1, 3, 224, 224).astype(np.float32)

# 执行推理
outputs = session.run([output_name], {input_name: input_data})

print(f"输出形状: {outputs[0].shape}")
print(f"推理完成！")

4.2 部署到不同平台

部署平台 推荐工具 优势 典型应用
云端服务器 ONNX Runtime + Docker 高性能，支持多GPU，易于扩展 AI服务API，批量推理
边缘设备 TensorRT / OpenVINO 低延迟，高能效，硬件加速 智能摄像头，工业检测
移动端 NCNN / MNN 轻量级，低功耗，跨平台 手机APP，AR应用
Web浏览器 ONNX.js / TensorFlow.js 无需安装，即开即用 在线演示，交互式应用
最佳实践建议：
  1. 在转换后立即使用ONNX Runtime验证模型正确性（精度对比）
  2. 针对目标硬件选择最优的推理引擎和优化参数
  3. 使用动态形状支持可变输入尺寸，提高部署灵活性
  4. 建立完整的模型版本管理 pipeline，跟踪不同格式的模型

五、总结与展望

ONNX 作为深度学习模型的"中间语言"，已经成为工业界模型部署的事实标准。通过掌握ONNX格式转换、优化和跨框架部署技术，开发者可以：

  • 打破框架锁定，自由选择最适合的训练框架
  • 一次训练，多处部署，大幅降低工程成本
  • 利用专用推理引擎获得最佳性能
  • 构建更加灵活、可维护的AI产品 pipeline

随着ONNX生态的不断完善，未来将支持更多新型算子、更高效的优化策略，以及更广泛的硬件后端，进一步推动AI模型的生产化进程。
