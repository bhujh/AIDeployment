一、NAS（神经网络架构搜索）基本原理

神经网络架构搜索（NAS）是一种自动化设计神经网络结构的技术，旨在替代手工设计，自动寻找在给定任务（如分类、检测）上性能更优、效率更高的网络架构。

核心三要素：

  • 搜索空间（Search Space）：定义待搜索的神经网络组件（如卷积类型、层数、通道数等）的组合范围。
  • 搜索策略（Search Strategy）：采用何种算法在搜索空间中探索，如强化学习、进化算法、随机搜索、梯度优化等。
  • 性能评估策略（Evaluation Strategy）：如何快速、准确地评估候选架构的性能，通常涉及代理指标（如验证准确率）与效率权衡。

传统NAS方法（如基于RL或进化算法）需要训练成千上万个候选模型，计算成本极高（数千GPU days）。近年来，权重共享与可微分搜索成为降低计算成本的主流方向。

二、One-shot NAS（单次传递NAS）

One-shot NAS 的核心思想是：训练一个超网（Supernet），其包含所有可能的子架构（子网络），通过权重共享，只需训练一次超网，即可评估任意子网络的性能。

典型流程：

  1. 超网构建：定义一个包含所有候选操作（如3x3卷积、5x5卷积、池化等）的图结构，每个位置是一个混合操作。
  2. 超网训练：在训练集上训练整个超网，使共享权重能够适应不同的子路径。
  3. 架构搜索：使用某种搜索策略（如随机采样、进化算法）在超网中采样子网络，并利用共享权重快速评估其性能（无需单独训练）。
  4. 重新训练：将搜索到的最佳架构从头训练，得到最终模型。

优点与缺点：

优点 缺点
大幅降低搜索成本（从千级GPU days降至数个） 超网训练仍需要大量计算与内存
权重共享使评估速度极快 权重共享可能带来评估偏差（训练-测试不一致）
可灵活支持不同的搜索空间 搜索出的架构通常需要重新训练才能达到最优性能

三、可微分NAS（Differentiable NAS）

可微分NAS将架构搜索转化为一个可微分优化问题，通过梯度下降同时优化网络权重和架构参数。

代表方法：DARTS（Differentiable Architecture Search）

DARTS 将每个节点之间的操作选择松弛为连续变量，使用 softmax 加权求和，从而使得整个搜索空间可微。

# 简化版 DARTS 混合操作计算
import torch
import torch.nn as nn

class MixedOp(nn.Module):
    def __init__(self, candidate_ops):
        super().__init__()
        self.ops = nn.ModuleList(candidate_ops)
        self.alpha = nn.Parameter(torch.randn(len(candidate_ops)))  # 架构参数

    def forward(self, x):
        weights = torch.softmax(self.alpha, dim=0)  # 将α转化为概率分布
        return sum(w * op(x) for w, op in zip(weights, self.ops))

优化过程分为两个交替步骤：

  1. 更新网络权重：固定架构参数 α，在训练集上通过梯度下降更新权重 w。
  2. 更新架构参数：固定权重 w，在验证集上通过梯度下降更新 α。

搜索结束后，根据 α 的值选择概率最高的操作，得到离散的最终架构。

DARTS 流程
  1. 构建连续松弛的超网
  2. 交替优化权重与架构参数
  3. 根据α离散化得到最终架构
  4. 从头训练最终架构
优势
  • 搜索效率高（GPU days 级别）
  • 理论优雅，端到端可微
  • 适合中小规模数据集
挑战
  • 内存消耗大（需存储所有候选操作）
  • 可能存在搜索崩溃（skip-connect 主导）
  • 离散化后性能可能下降

四、NAS用于自动模型轻量化

将NAS与模型压缩目标（如参数量、计算量FLOPs、延迟）结合，可自动搜索出高性能、低成本的轻量化模型。

常见技术路线：

  • 多目标NAS：在损失函数中加入模型大小、计算量等约束项，如 Loss = CrossEntropy + λ * FLOPs。
  • 硬件感知NAS：在搜索时直接测量或预估目标硬件（如手机、嵌入式设备）上的实际延迟、功耗，并将其作为优化目标。
  • 压缩感知NAS：在搜索空间中直接集成轻量化组件（如深度可分离卷积、通道剪枝、量化操作），让搜索过程自动选择高效结构。

典型工作对比：

方法 核心思想 轻量化目标 搜索成本
MobileNetV3 NAS + NetAdapt 联合搜索 参数量、延迟（手机） 数千 GPU hours
EfficientNet 复合缩放系数 + NAS FLOPs、参数量 数千 GPU days
ProxylessNAS 硬件感知的可微分NAS 延迟、内存占用 数十 GPU days
FBNet 硬件在环（HAL）搜索 实际硬件延迟 数百 GPU hours

实践建议：对于工业部署，可结合 One-shot NAS 进行快速原型搜索，再使用 硬件感知微调，在目标设备上进一步优化延迟与能效。

五、总结与展望

NAS 已成为自动化机器学习（AutoML）的核心组成部分，尤其在模型轻量化领域展现出巨大潜力。未来趋势包括：

  • 零成本NAS：无需训练即可评估架构性能（如基于网络态射、初始化性能预测）。
  • 跨任务/跨平台NAS：搜索出的架构能够快速迁移到不同任务或硬件平台。
  • NAS与量化/剪枝联合优化：将压缩技术直接嵌入搜索空间，实现端到端的轻量化模型生成。
  • 绿色NAS：关注搜索过程的能耗与碳排放，发展更环保的自动化设计方法。

掌握NAS技术，能够帮助工程师在资源受限的场景下，自动设计出兼顾精度与效率的神经网络，是模型压缩与部署的关键技能。
